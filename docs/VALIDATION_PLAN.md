# План валідації: AI-assisted coding з людською перевіркою (затверджено 2026-10-25)

Джерело: зведене повідомлення ChatGPT від 2026-10-25, погоджене Андрієм. Змінювати дизайн, таксономію, пороги чи правила включення — лише окремим рішенням Андрія (позначка `⚑ РІШЕННЯ ПОТРІБНЕ`).

## 1. Учасники

| Роль | Хто | Що бачить |
|---|---|---|
| Алгоритм | `src/v3/attribution.py` (v3.2 + ⚑7) | — |
| LLM-кодер 1 | окремий агент Claude, що не бачив алгоритму, прогнозів і аудитів | лише `validation/blind/CODER_INSTRUCTIONS.md` і пакет повідомлень |
| LLM-кодер 2 | **новий чистий чат ChatGPT** (не поточний аудитор) | те саме |
| Людина-арбітр | Андрій | текст і анонімні варіанти A/B/C (без указання, хто їх дав) |

## 2. Етапи

1. Сліпі пакети: 15 × 100 (`validation/blind/batch_*.jsonl`; лише item_id, channel, text). Формат відповіді — JSON Lines (розділ 6 інструкції). Перевірка — `python -m src.v3.blind_io check|merge`; зміст відповідей LLM не виправляється.
2. Обидва LLM-кодери кодують усі 1 495 повідомлень незалежно. Сирі файли незмінні: `validation/llm/claude_blind_raw.jsonl`, `validation/llm/chatgpt_blind_raw.jsonl`.
3. Порівняння алгоритм / Claude / ChatGPT за полями: зміст, промо, є джерело, спосіб, прямі джерела (назва + тип), вкладене/посередник, пункти призначення.
4. **Розбіжності** (будь-яке поле не збігається) — Андрій перевіряє **100%**.
5. **Одностайні** випадки — випадкова перевірка **250** (seed фіксується до початку): 100 «джерело є», 100 «джерела немає», 50 цільових (hyperlink, both, кілька джерел, вкладені, рідкісні типи). Страти не перетинаються.
6. Інтерфейс однаковий для розбіжностей і перевірки збігів (Андрій не знає, що перед ним); порядок варіантів випадковий; показуються лише поля, де є що вирішувати.
7. Метрики — на **human-verified reference set** зі зважуванням `weight = N_страти / n_перевірених_у_страті` (окремо в частині A і B).
7a. (2026-10-26, аудит ChatGPT) Перед перевіркою: V0001–V0100 виключено (витік) і замінено R0001–R0067; одностайність — за суворим зіставленням назв; ⚑8-випадки — усі до перевірки (страта F_flag8); Андрій спершу кодує сам (джерело, прямі джерела з типом, зміст, реклама) — ці відповіді фіксуються до показу варіантів; ваги двоетапні, бутстреп дворівневий; «не впевнений» = незавершене.
8. Звіт VALIDATION і рішення GO / NO-GO; повний корпус — лише після GO і затвердження Андрієм.

## 3. Термінологія

- **human-verified reference set** — перевірені Андрієм випадки; на них усі основні метрики.
- **consensus-coded set** — одностайні, але не перевірені людиною; **не** gold standard.
- У статті: «AI-assisted content coding / automated source-attribution classification with human validation». Не писати «ручний контент-аналіз 1 495 повідомлень», «LLM gold standard», «повністю автоматична класифікація».

## 4. Метрики і пороги (не знижуються)

| Показник | Поріг | 95% CI, нижня межа |
|---|---|---|
| has_explicit_source precision | ≥ 0,95 | ≥ 0,90 |
| has_explicit_source recall | ≥ 0,90 | ≥ 0,85 |
| actor precision / recall | ≥ 0,90 / ≥ 0,90 | бажано ≥ 0,85 |
| source type macro-F1 end-to-end | ≥ 0,85 | — |
| denominator accuracy; substantive recall | ≥ 0,95; ≥ 0,98 | — |
| destination type accuracy | ≥ 0,95 | — |
| суттєві помилки серед перевірених одностайних | ≤ 5% | інакше NO-GO |

Також: conditional type F1, attribution method accuracy, nested accuracy, destination extraction P/R, κ Claude↔ChatGPT, κ Андрій↔Claude, κ Андрій↔ChatGPT (κ між LLM — показник узгодженості, не точності).
Recall і загальна precision — на випадковій частині A (зважено); частина B — precision за механізмами.

## 5. Що зберігається для кожного рішення Андрія

item_id, msg_id, channel, date, хеш тексту, страта, сирі відповіді алгоритму / Claude / ChatGPT, показаний порядок варіантів, рішення Андрія, нотатки, час, тип (розбіжність / перевірка збігу), ймовірність відбору, вага.
