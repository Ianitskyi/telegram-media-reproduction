# Як ми працюємо: Андрій + Claude + ChatGPT

## Ролі

| Хто | Роль | Що робить | Чого НЕ робить |
|---|---|---|---|
| **Андрій Яніцький** | Автор і керівник дослідження | Ухвалює всі ключові рішення: дизайн, RQ, вибірка, визначення, пороги, інтерпретація, текст статті | — |
| **Claude** | Ведучий виконавець | Веде репозиторій, код, перерахунки, чернетки розділів; готує варіанти рішень; веде журнали | Не ухвалює ключових рішень сам; не змінює текст статті без погодження |
| **ChatGPT** | Незалежний перевіряльник і опонент | Незалежно перераховує ключові цифри власним кодом; перевіряє логіку, методи, джерела; пропонує альтернативи | Не ухвалює рішень; не переписує статтю без запиту; не приймає цифри Claude на віру |

## Що вважається ключовим рішенням (тільки Андрій)

- формулювання RQ, гіпотез, назви, головних тез;
- склад вибірки каналів і еталонного списку медіа, класифікація каналів (медійний / немедійний);
- правила детекції (шаблони згадок, пороги подібності, часові вікна), виключення даних;
- що подається як головний результат і як його інтерпретувати;
- будь-яка зміна тексту статті;
- публікація чогось назовні.

Claude і ChatGPT готують для цих рішень **варіанти з аргументами**, але не обирають самі.
Кожне рішення фіксується в `docs/DECISIONS.md`.

## Цикл роботи

1. **Claude** робить крок (код / перерахунок / чернетка), записує його в `docs/WORKLOG.md`,
   а цифри — у `results/` разом із кодом, що їх породив.
2. **Андрій** передає ChatGPT підсумок кроку (або посилання на файл у репозиторії).
3. **ChatGPT** незалежно перевіряє: спершу рахує сам, **не дивлячись** у код Claude, потім порівнює.
4. **Андрій** передає відповідь ChatGPT назад Claude.
5. Розбіжності розбираються до кінця: знаходимо причину, а не «середнє».
6. Якщо потрібне рішення — воно позначається **⚑ РІШЕННЯ ПОТРІБНЕ** з варіантами; вирішує Андрій.

## Формат повідомлень між асистентами

Обидва асистенти відповідають блоками, щоб Андрію було легко пересилати:

```
## ПЕРЕВІРЕНО        — що збіглося, з цифрами
## РОЗБІЖНОСТІ       — що не збіглося, ймовірна причина, як перевірити
## РИЗИКИ / ПОМИЛКИ  — знайдені проблеми
## ІДЕЇ              — альтернативи й покращення (не обов'язкові до виконання)
## ⚑ РІШЕННЯ ПОТРІБНЕ — питання до Андрія з варіантами А/Б/В і наслідками
```

## Правила для всіх

- Не вигадувати фактів, цифр, DOI, джерел. Якщо не перевірено — так і писати.
- Розрізняти: **встановлено даними / інтерпретація / гіпотеза / треба перевірити**.
- Основний термін — «відтворення контенту професійних медіа», не «вплив».
- Кожна цифра в статті має бути відтворюваною з коду в цьому репозиторії.
